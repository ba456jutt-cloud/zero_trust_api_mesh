# External Dataset (APISentry) — Feature Availability and Limitations

## Dataset Summary
- Source: Zenodo record 22658802 (APISentry, anon dataset)
- Rows: 11,310 (6,611 normal, 4,699 attack across 7 attack types)
- Columns: 27 (pre-standardized features + multi-class labels)
- Attack coverage: SQLi, parameter tampering, brute-force, credential stuffing,
  BOLA, API flooding, token replay — exact match to our 7 attack vectors

Summary: 8/12 direct, 2/12 proxy, 2/12 unavailable (0.0 default).

## Honest Implications

1. **scope_mismatch feature is non-functional on external data.** This means the
   specific "scope-aware BOLA detection" capability is demonstrated ONLY on our
   synthetic FAPI simulation, not on the external dataset. External BOLA
   detection relies on `distinct_accounts_ratio` and `endpoint_risk_weight`
   instead.

2. **benford_deviation feature is non-functional on external data.** The Benford
   financial-amount anomaly detection is demonstrated ONLY on synthetic
   Pakistani Rupee transactions.

3. **External evaluation measures 10 of 12 features** effectively. Any metric
   improvement that would have come from scope_mismatch or benford_deviation is
   NOT validated externally.

4. **The synthetic data pipeline remains the only place where the full 12-feature
   vector is exercised end-to-end.** External validation is therefore a
   PARTIAL cross-check, not a full replacement.

## What This Means for SBP Sandbox Application

In the application and defense, we will state honestly:
- The full 12-feature zero-trust mesh (including OAuth scope enforcement and
  Benford financial anomaly detection) is demonstrated on the synthetic FAPI
  simulation aligned with SBP Open Banking Regulations 2026 (draft).
- Independent external validation on APISentry confirms detection capability
  for 7 attack types using the 10 features available in that dataset.
- The 2 unavailable features do not invalidate the 10-feature results; they
  simply restrict the claim of external validation to a subset.
